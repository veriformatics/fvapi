## Intent

fvapi is an API for formal verification. Someone who wants something formally verified can call it. When our private library can speed up the work, fvapi uses the library, and it still gives the caller everything that they need to prove the result true themselves. fvTrace and fva use fvapi, also for their own normal work. Future applications can use it too, including applications that other people write.

fvapi runs on `vflab`, a machine that it shares with fvdep. vflab does the actual work, stores the artifacts and holds the library. The Claude sessions that control fvapi run on the founder's desktop, and the fvapi repository lives there. The sessions use vflab for the work, for the storage of artifacts and for the upkeep of the machine. vflab works on its library only when a session starts that work.

- Lookup (user rulings): keys `spec_id` | `artifact_sha256` | `statement_digest` (versioned structural digest of a Lean statement, computed caller-side by `fvapi digest`; replaces the statement-text key, user notified); every supplied key must point to the returned entry (the same entry revision, not necessarily the same target: user ruling); any disagreement = a miss logged as demand, naming each key's matches (a proof about another build never answers). Several matches → one pick: coverage first, then newest revision, then entry id, made a total order (pairwise it cycles: A={x,y} beats B={x} by coverage, B beats C={z} by recency, C beats A by recency): the pick = the newest (then lowest-id) match that no other match strictly contains; the rest follow by peeling these undominated layers in turn, newest then id within each layer; the other matches = a total count + pages that name every one (user notified).
- Statement digest (sd1 spike; MAIN ruling after scientist-6 + consultant-41/42/43 + advisor): `statement_digest` = `sd1:` + 64 lowercase hex = SHA-256 Merkle hash of the selected declaration's closed elaborated TYPE under its ordered universe-parameter list (position per label, unused slots kept); exact byte function + conformance vectors `docs/digest-sd1.md` (frozen: an identity-rule change = a new tag; a changed elaboration input alone keeps the tag). Referenced constants keep full structured names; metadata, binder/let labels, BinderInfo + let-nondep erased; every TYPE argument kept, proof-valued ones included; no reduction; the declaration's own proof, name + module, dependency bodies + toolchain/environment salt excluded. Routing key, never equivalence, compatibility or acceptance: a theorem is verified only by the caller's challenge, axiom allowlist, comparator + kernels (`Answer guarantee`); a hit stays a routing hit (HTTP 200; CLI 0 unchecked); a failed re-check = verification failure (no verified success), neither a miss nor a demand row. Default lookup = selected-only (one pick + paged other matches, no automatic retry): a later compatible match can exist after a false route; a caller may verify alternatives explicitly; a bounded opt-in retry = a U9 contract decision. Failures: invalid or unresolved input + cooperative exhaustion → typed failure, no digest; forced OOM, signal or deadline → nonzero exit, no usable digest; caller-binding gaps (internal-name targets, candidate-axiom roots) limit re-check, not hashing. Evidence (Lean 4.35.0 + capsule Mathlib on vflab; `.agent/archive/sd1-spike.md`): A1 mechanically selected under the recorded check interpretations, not every literal frozen condition; A2 screened out, A3 never run. U5 owes: the `fvapi digest` operation contract first (selector, declaration kinds, import/options boundary, output, failure mapping), then encoder refinement proofs (erasure, memoization, root) + property tests under `Self-verification`; vectors = conformance examples, the spike encoder = a differential aid. Cross-release drift unmeasured (`.agent/deferred.md`).
- Delivered-bundle terms (user ruling): decided later; until then every private-library bundle states "provisional: internal evaluation only", and final terms are set before any outside caller receives a bundle.
- Re-check trust (user ruling): the API stays one request → answer + bundle; the optional re-check runs caller-side in the open-source client against a client-held axiom allowlist (default `propext`, `Classical.choice`, `Quot.sound`, caller-editable); the bundle's own axiom list is displayed, never trusted; plus an optional container for a re-check independent of the caller's Lean install, built locally from the committed Containerfile; public-registry publication: not yet (user ruling). One call, two transfers (user ruling): the caller makes one call (CLI, MCP, Lean library); the answer carries the bundle's sha256 + path, and the client fetches and verifies the bundle inside that call.
- Library work (user rulings): no proving automation this phase. New-proof requests + lookup misses become queued rows (queued → being proved → added, shown in the console), kept in a gitignored file in this repo mirrored from vflab's queue (the repo is public). The founder proves rows in Claude sessions from time to time: library development that picks its own targets, never fulfilling a specific outside caller's request (subscription terms). Admission = the `Answer guarantee` kernel policy alone, no statement review gate. No unattended library work (user ruling, Intent): every library run on vflab starts from a session, no idle loop; the weekly CI + CodeQL schedules, Renovate and other sessions' repo work stay as they are.
- IMPLEMENT scope (user rulings): the service ships library lookups, existing checkers + new-proof requests as queued rows (`Library work`). One founder account (one key, one history) = this phase's only caller. Acceptance = the founder through the API, the CLI + the MCP adapter, plus contract tests that run fva's flow (lookup → fetch → `fva trust`) and fvTrace's flow (lookup → fetch → re-check → receipt) against the live service; fva + fvTrace adopt the client in their own sessions. Third-party onboarding (identity, per-application keys, limits, payment, ZDR, isolation, final terms) later.
- Request data (user rulings): requests feed library building by default; the only opt-out = paid zero data retention (ZDR: no request content or result stored after the response; kept: caller id, time, route, status), which also removes the caller from library learning; a caller never sees another caller's requests, answers or demand. ZDR + per-caller isolation ship with third-party onboarding; every stored record carries a caller id. Operator blindness (goal: a proof that the operator cannot read sensitive request content while the library still learns) = research only this phase: a design + proof plan in `docs/`, the mechanism later. Prototype's global demand + answer logs = placeholder.
- Self-verification (user rulings): fvapi itself is formally verified. Trust test: a component stays trusted only where users of a formal-verification service would reasonably accept it (e.g. the Lean compiler + runtime, the OS); whatever they would expect verified is verified, by us or upstream (e.g. Lean's verified kernels con-leche + con-ron, HACL* hashing).
- Stack (user ruling): Lean 4 throughout (toolchain 4.35.0 now) — server, client, Lean caller library, MCP adapter + proofs in one Lake package; library entries are Lean.
- Answer guarantee (user ruling): exact theorem, labelled. A theorem answer is checked caller-side against the caller's own statement + axiom list: Lean's default kernel + ≥1 kernel of another implementation accept, none rejects, crashes or times out (a kernel may decline only for a named unsupported feature), and the answer names the accepting kernels (incl. con-leche + con-ron). A checker answer carries a kernel certificate over the caller's exact input bytes; past the time budget its verdict is labelled `compiled evaluation (trusts the Lean compiler)`. Artifacts are named by their exact bytes; a partial answer is labelled partial, never a full success. Certificates = a time-boxed research unit this phase (user ruling; spike v3.2: all 60 builds of 1–64 KiB certificates exhausted 8 GiB, a streaming byte cursor is the measured lead); a request gets a certificate when its certificate closes within the measured full-call budget, otherwise its verdict carries the compiled-evaluation label; certified sizes are reported as observed, never promised for a size class.
- Audience + surfaces (user rulings): programs + agents first — the API, the CLI, the Lean caller library + a small stdio MCP adapter over the same API (this phase) = the product; the console = the founder's inspection surface.
- Backup (user ruling): off-machine backup stays deferred (`.agent/deferred.md`); accepted risk = losing vflab loses the library and its history until a later phase.
- Delivery order (user ruling): breadth — each layer built for every feature in turn; no vertical first slice.
- Server runtime (spike v3.2): Std.Http with batched receives (64 KiB: p99 ≤ 19.3 ms in all 25 fixed 20 req/s windows on vflab, 566,768 correct responses; the 1-byte receive workaround missed 50 ms); the connection-admission cap + receive size come from the server unit's matched resource experiment (64 concurrent near-full bodies cost +259–283 MB RSS); the M1 numbers are a LAN benchmark, not a production SLO; toolchain 4.35.0 with one pinned, tested runtime artifact (4.35.0 lacks Std.Http/Async fixes #15192, #15174, #15443, #15469; #15174 touches the C++ runtime); a toolchain upgrade keeps replay of proofs made under 4.35.0.
- Verification profile + gate (spike F2/F6): one versioned verification profile = checker + exporter binaries, runtime image, export format, comparator's fixed targets, kernel policy, canary corpus; any change replays the compatibility corpus. Replay = per claim: proof root + full closure exported with comparator's fixed targets, compared against an independent challenge, each kernel run alone under caps (all six ACCEPT in the spike); never whole-package `lake check --paranoid`. Claims = domain-local closed spec modules listed in a claim inventory with their shipped call paths (`fva trust` replays a spec module's claims together). `fva trust` + `fvamut` come from a pinned clean fva commit and audit this repo alone; a delivered package earns the `Answer guarantee` through the caller-side challenge path.
- Gate + CI (`Sessions + placement`): `tools/gate.sh` reads public inputs alone; `tools/vflab-run` runs it on vflab in a per-worktree workspace reset to the worktree's exact file set before each run, under a lock the run itself holds (persistent Lake + tool caches), inside a top-level gate slice beside `system.slice` with low weight + aggregate CPU, memory, task + root-disk bandwidth caps; its exit-status propagation (signals, OOM, timeout included) proven on the real host; GitHub CI runs the same gate secret-free and host-independent; every dependency names its scanner + update path (CodeQL has no Lean; Renovate custom managers for the Lean toolchain + Lake manifest); an unavailable tool = gate incomplete, never green.
- Store: versioned envelopes (store root, entry payload, bundle, verification profile) independent of API `/v1`; stored bytes are never rewritten (migrations publish new objects); entry revisions carry typed target + subject bindings (coverage = the proven-target set); one serialized writer commits a generation root; each release states its store compatibility and a rollback switches binaries over the same store; request records carry principal, credential, scope + policy at receipt, audit metadata apart from content; admission + delivery receipts record build, verification-profile + comparator identities. Quotas + GC and the incident quarantine path = deferred (`.agent/deferred.md`). The dev store driver's E-A40 preaccept active-work bound is proved in U4A, not rescoped to U4B/U7 (user ruling). History storage (user ruling, Tier B "Now"): the copied history lists change before the structure-dependent E-A40 proofs, which are then proved once on the new storage; expected load < 1,000 recorded requests/day over the first two years (user estimate). Seam (MAIN ruling: spikes S1 typed twins beside vs S2 in place, scientist-17, consultants 55–57, advisor): S2 — `State`'s nine history fields + `Row.attempts` become `Hist α` (newest-first, O(1) push, O(1) length via a cached `size` (store walks SW-K8), noncomputable `Hist.toList` view) and the reopened proofs adapt; reason = one production State representation + E-A40 cost bound to the production functions, not a measured memory or effort win; unit contract `docs/contracts/U4A-tierb.md` (C1–C11; first checkpoint = the functional proof closure against the unchanged spec + premises; reversal tests R-a..R-c). Store walks (user ruling, "Design first"): the list change alone leaves paths whose cost grows with the stored data (the seal's whole-closure walk per batch, the full-state checkpoint rebuild, …) ⇒ alongside the list change, each such path gets a designed change with a written contract; before the first E-A40 memory proof MAIN returns to the user with a concrete proposal + its cost. Index checkpoints (user ruling on that proposal, store-walk K2): chunk format v2 by in-place erratum of P21/P23 (no U4-format store exists outside tests): a chunk holds sorted items alone (no `source`, no absolute ordinals) and is reused by content address; chunks hold 512–1,024 items (one may hold fewer); a checkpoint writes the chunks changed since its kind's last checkpoint + the chunk directory once (built bottom-up, equal to the append fold; one prepare); the blind-suite corrections this needs are approved (steward path). Remaining growth = the directory, ≈ one 1,024-entry node per ~800,000 index entries per checkpoint; a counted directory (cost ∝ change alone) = a later migration if an index nears that size. The rest of the proposal (K1 incremental live set, N6 generation index + certificates, K8 cached history length, …) = MAIN's plan; each change gets its written contract + a consultant before code.
- Row history (user ruling, store walks SW-N6): one proof request is expected to collect fewer than 100 attempts. Each update re-reads that request's whole attempt history in its construction walks (K4) and its head + meaning checks (N6), so its time and peak memory grow with that request's own history (measured: one update ≈ 9 ms at 8 attempts, 38 ms at 64, 340 ms at 512; batch peak ≈ +10 KB per attempt, arm driver 06a8a520): accepted and stated as a per-request term in the E-A40 memory bound (a request whose term exceeds the configured batch limit is refused until the limit is raised); no certificate cache (SW-N6b retired); M4 T-rowcheck + T-headcheck close by this ruling as charged exceptions (`docs/contracts/U4A-tierb-m4.md` §9 R15); the construction check's list search (quadratic in the history) becomes a keyed lookup (MAIN, row SW-K4a).
- Rows: a row = immutable origin (request | miss) + challenge facts, plus work attempts under a revision counter; misses with the same keys coalesce into one open row with a count (user notified); a closed row stays closed and a later miss opens a new one; a row without a statement (artifact-only miss) gets its challenge when the founder resolves it; a claim expires and is recoverable; `fvapi rows sync` mirrors incrementally by sequence number.
- Interface: API v1 = `docs/api.md`; one outcome taxonomy across HTTP, CLI exit codes, MCP + `Fvapi.Client`; a checker request names the checker spec + revision the caller expects and carries the exact input bytes; the answer reports semantic verdict, verification status (`kernel_certificate` | `compiled_evaluation` | `failed`) and coverage as separate fields, and a partial answer never maps to a success code; lists page by cursor under byte bounds; additive changes within v1, clients fail closed on unknown required features; wire types stay separate from store types. Accepted cost: caller-side verification takes tens of seconds (spike: 32.7–33.9 s for a 22.6 MB export — binding ≈ 3 s, comparator ≈ 6.5 s, six kernel replays ≈ 23 s); reducing it never drops a required check.

- Mutation currency (user ruling, P7b frozen): per-cell content keys + kill/build witnesses + rulings bound to their module's elaboration context and a reviewed authority manifest, kept by fvapi's harness over the pinned fvamut engine; every mutation build/test cell sandboxed (bubblewrap, pinned userspace, no network), credit scoped to that stage; narrow per-domain test + dev executables; strict survivor currency; full refresh at IMPLEMENT close + each MAINTAIN code-review request; contract `docs/contracts/U2-P7b-mutation.md`.
