# Request strip

Premise = chart-recorder log as the entire page; compose the next request at its head, read the latest verdict + touched proof path, unfold earlier requests down the strip.

Palette: sheet #ffffff; backing #e9edf2; ink #262840; violet #51418c; rule #7d8595; demand #943d36. Violet = active path, not a proof-trust assertion; verdict + node labels name accept/reject explicitly.

Type: system sans = controls/prose, 14/16/22/30 px; system monospace = readout, JSON, timestamps, hashes, 12/14/36 px. Prose ≤76ch. Smaller readout than u02; no enamel, bevels, bolts or dark chassis.

```
[fvapi     Request strip                        vflab]
 time      [Next request                             ]
           [entry selector      | editable input tray]
           [lookup spec + action| Run check          ]
 now       [latest verdict | reason + timing         ]
  │        [entry — subject — grouped files — runtime]
  │        [proof package: statements, replay, hashes ]
 time      [earlier lookup/check/miss, expandable     ]
 time      [earlier lookup/check/miss, expandable     ]
           [Answers / Demand filter + key counts     ]
```

Distinctive = one continuous ruled paper strip with a punched edge; request composition is its first row. New request expands in place above earlier records; each expanded row retains its own touched graph + evidence. The graph is a compact horizontal path, not a separate application view. Closure directories collapse counts; files + hashes remain expandable. Misses stop at a dashed, unattached demand node. Recorded replay stays explicit. Native disclosure supplies text graph alternative, not a graph/list mode. Narrow screens stack controls and flow graph vertically. No motion.

Finish = relative API only; complete entry evidence; checker selected by check presence rather than catalog order; eleven states captured + inspected; commit only this directory.
