# Blind-suite expectation corrections (user ruling; adapts CLAUDE.md `Engineering`: "a threshold, case or gate changes only in its own unit — never the unit it grades — on evidence the check errs against the contract")

- Steward-ruled corrections: the independent table steward's ruling, citing exact table rows, that a blind-suite expectation contradicts the frozen contract tables = the evidence; the blind tester applies the correction on the suite's own branch. Each correction is ledgered per case (id, ruling, old → new expectation) in the tester's deliverable.
- Implementers never edit blind suites. A correction that drops, skips, demotes or weakens a case, or changes a contract promise rather than a misread of it, still goes to the user first.
- A contract amendment that makes existing fixtures invalid (a required input missing) may be adapted by the implementer of that amendment (MAIN; any other implementer with MAIN's per-change approval): one separate commit, assertion and case code byte-identical, affected ids listed, the diff reviewed by MAIN before merge.
