## Delivery + freeze boundary

- U4A = formats + pure model + claims, across every feature. U4B = durable engine + crash refinement + recovery, across every feature. U4C = benchmark + compatibility + qualification/integration. U4 closes only after A + B + C; no durable-store claim at A, no production performance claim from B. U5 onward may consume frozen A types; durable service use waits for B + C's applicable evidence. This preserves breadth, not a vertical first slice.
- (ruled R1) Three explicit checkpoints U4A → U4B → U4C; no change to feature order, phase or required checks. The exact tables are U4A's first deliverable: drafted, independently reviewed and frozen before any blind tester or native build.
- U4A's first deliverable = `Payloads-v1`, `Commands-v1` (commands/results), `Driver-v1`, `Syscalls-v1`, `Crash-v1` (crash model) tables: draft, independently review and freeze them before any blind tester or native build. They are required U4A appendices/companion contracts, not names for builders to fill from their own code. The five reviews do not supply those exhaustive tables; this contract specifies their content + acceptance.
- Table completeness: Payloads-v1 = every envelope/control/kind member, scalar/cardinality/whole-message bounds, optionality, duplicate/extra-member policy, array/key order, typed reference, attribution, operational-reachability edge, cross-object predicate, outcome precedence, canonical bytes + addresses. Commands-v1 = closed typed command/result algebra, preconditions, exact serial effects, failure identity, allocations, audit behavior, basis snapshot, no-op rules. Driver-v1 = exact invocations/byte framing/outputs/errors/exits/hooks. Syscalls-v1 = exact native symbols/flags, operands, ownership/guards, retry eligibility/budget, result + primary/secondary errors. Crash-v1 = independent persistence machine, assumptions, cut choices, acknowledgement oracle + init/error cases.
- All work runs on vflab through the recorded runner; public CI stays host-independent + secret-free. Committed fixtures/benchmarks = synthetic/public; private library material stays outside git. GC, quotas, incident quarantine, backups, third-party isolation/ZDR, restart-stable cursors and automated library proving remain deferred. Losing vflab still loses the unbacked-up library/history.

## U4A Formats + pure model + claims

### E Objects

- E1 Two namespaces: raw blobs (archives, exports, retained exact request/check bodies, challenge/profile/evidence bytes) at `blobs/<h0h1>/<h2…h63>`; canonical JSON records at `records/<h0h1>/<h2…h63>`. h = lowercase SHA-256 of the exact file bytes, not of a wire value or display identity. Envelope = `{"format":"fvapi.store.v1","kind":K,"version":n,"requires":[feature…],"payload":P}`. `BlobRef` and `RecordRef expectedKind` are distinct types; a reference fixes namespace + expected kind and any asserted size. U2 `profile_id`, statement digest, entry tuple and store object address are distinct types. Only validated digest components/fixed names enter paths (P).
- E2 Read outcome precedence: validate reference/path/file type → read exact bytes → verify asserted length + digest → class branch. Missing committed reference, wrong node type, size/hash mismatch = `corrupt`; operational read failure = typed `io`, never fabricated empty bytes or a partial digest. Blob branch returns exact bytes, never JSON-decodes. Record branch requires complete U3 decode, exact envelope/member types, canonical reprint equality and well-formed header declarations; otherwise `corrupt`. Version is positive; `requires` is a strictly byte-sorted duplicate-free list of the table's feature identifiers. Well-formed unsupported format/version/required feature = `unsupported`; supported payload outside its exact schema/local/reference relation = `corrupt`. A known kind inconsistent with the typed reference = `corrupt`. No absent-field defaults or partial record. Payloads-v1 fixes every mixed-failure precedence, including unsupported declarations + malformed fields. Known v1 records admit exactly their listed members; wire response tolerance is not inherited by persistence.
  - (ruled R3) Total precedence: IO errors remain separate → invalid shape/types/noncanonical generic envelope = `corrupt` → well-formed unsupported format/kind/version/required-feature declaration = `unsupported` → known kind inconsistent with the typed reference = `corrupt`. Generic canonical-envelope validation precedes unsupported checks; no speculative payload decode for an unsupported declaration. Payloads-v1 fixes exact mixed-error controls.
- E3 Immutable publication: exclusive own-format regular temporary in its final pinned parent → complete write → original-description `Writer.sync` → explicit `Writer.close` → publish without replacement. No final byte rewrite. Existing name succeeds only after complete exact-byte comparison + expected file type; size/hash/name existence alone is insufficient. Equal bytes establish identity, not durability. A dependency already validated in the previous durable closure inherits that invariant; any other reused name, including an equal-byte orphan, must establish its file/name/ancestor barriers before the new generation relies on it. Reopening after a reported writeback error is not repair. Unequal bytes/wrong type fail closed; no clobbering fallback.
  - (ruled R4) One qualified no-clobber primitive per filesystem profile; no silent runtime fallback. Prefer `renameat2(RENAME_NOREPLACE)`. U4B qualification measures support on vflab's ext4 and OpenZFS. If a profile lacks it, that profile's qualified primitive is link + unlink, with its own operations, errors and ownership rules. Syscalls-v1 specifies each required backend; an unqualified profile cannot be used.
- E4 Payloads-v1 covers domain families `entry-revision`, `row-origin`, `row-revision`, immutable row-attempt facts, `request-record`, `request-content`, `answer`, `admission-receipt`, `delivery-receipt`; evidence/profile/challenge descriptors; structural `segment`, `index-checkpoint`, selected history-node representation, `generation`; and CURRENT. The exact kind registry/tags are part of the freeze tables. Histories/maps/evidence grow through bounded referenced objects, not unbounded inline arrays or deeply nested JSON. Every complete envelope satisfies U3 J1; a wire-valid nested `any` need not remain valid in an extra store wrapper, so raw bodies/outputs/evidence use typed blobs where needed. Maximum encoded sizes derive from the frozen schemas, not samples. U2 profile and U8 bundle formats remain independently versioned; their exact bytes/format identity are preserved through typed references. No current wire encoding becomes persistence law.
  - (ruled R2) Every record payload carries `caller_id`; structural/profile/generation/index/segment records use the sole founder caller as store provenance this phase. Raw blobs are not records; ownership/visibility follows typed caller-owned reference chains. Shared entries/bundles remain shared; attribution never makes library content founder-private.

### D Domain records

- D1 `entry-revision`: unique entry id + contiguous revision (first 1), presentation fields, typed sole Subject, nonempty bounded typed Targets, optional Checker, toolchain, licence_spdx, terms, archive BlobRef + exact packed/unpacked sizes, admission-receipt ref, admitted_ms + admitting caller. Scalar/cardinality domains support the corresponding API projection without aliasing wire types. Coverage = set of complete typed targets, never list multiplicity; sole `subject.artifact_sha256` binds every target. `spec_id` and statement digest may match different targets of the same revision, per frozen W1a. Retain all admitted revisions; no latest-only index shortcut. Private-library terms = exactly `provisional: internal evaluation only`. Entry/receipt/discovery effects publish atomically. U12 supplies the independent challenge + legal admission under the kernel policy alone; a claim label, solution-supplied digest or solution bundle is not that challenge.
  - (ruled R5) The entry's sole admission-receipt path reaches independently provisioned challenge/snapshot bytes + identity, including rowless/seed admission. Preserve one authoritative evidence path, not a second mutable source. Exact challenge format/provenance = U12, exact storage descriptor = U4A. No entry↔receipt hash cycle: receipt binds entry id/revision + receipt-excluding subject/target/archive/challenge projection, not the hash of the entry that contains it.
- D2 `row-origin`: immutable row id, caller_id, origin `request` | `miss`, exact normalized Keys, created_ms + original request-record ref. Request origin additionally retains original statement, optional note + optional idempotency key; Keys = `{}` or exactly `{artifact_sha256}`. Miss Keys = complete nonempty lookup Keys; original request facts are never replaced by a later coalesced miss. Request statement is its effective challenge fact; miss statement is absent until one resolve. Exact raw transport content remains separately referenced (D4).
- D3 `row-revision`: row id/caller, positive contiguous revision, immutable origin ref, state, positive count, immutable-once-present resolved challenge fact/ref, attempt-history head + attempt_count, optional EntryRef/reason, unique allocated change seq + updated_ms. Identity/caller agree with origin; every revision retains established origin/statement/keys/challenge. Request rows always count=1; miss rows use Q2. State-dependent EntryRef/reason obey W's stored Row relation. Attempts are immutable events/versions under a bounded referenced history; ending an active attempt adds a fact/version, never rewrites old bytes or copies every old attempt into each row revision. The table specifies the fold to each numbered attempt's latest state, the history pinned by each revision and its newest-first paged projection. U4 owns structural/reference validity, expected-revision CAS, revision/seq allocation + atomic index/history effects. U13 owns workflow legality, claim expiry + attempt transitions; arbitrary malformed emitted records are never accepted merely because a higher layer supplied them. U13's policy preconditions/discharge obligations remain explicit.
- D4 `request-record` = completed immutable audit metadata: caller/principal, credential id (never secret), received scope + policy snapshot/immutable refs, canonical route id without sensitive captures, received_ms, terminal HTTP status + semantic outcome, optional request-content ref. No copied body/theorem/output/content-bearing query in audit fields; no reconstruction from the current credential later. `request-content` = caller-attributed descriptor of exact path captures/query facts + body mode/byte length/raw BlobRef; normalized typed facts may supplement, not replace, exact bytes. Binary check bodies and large raw JSON bodies are not a single JSON string. Required audit/content/result effects commit atomically with the operation. A pre-completion event, if retained, is a separate immutable event, not an audit record later mutated into completion.
  - (ruled R6) Freeze a minimum retained-route table: authenticated successful mutations + lookup/check answer events and explicitly declared semantic failures; ordinary reads/schema rejections are recorded only where their owning route requires it. Each promised retained effect is explicit in Commands-v1; no blanket audit guarantee. Preserve API admission's `publishes nothing on any failure`: no durable admission-failure audit is added. Health/unauthenticated rejection use content-free operational events; pre-admission busy/store failure never promise a durable record. Accepted equal-key replays may append audit history but never a second row/change.
  - Retention policy this phase = retained content + library learning. Content absence is only an explicitly named content-free/future format seam, not ZDR. Future ZDR must omit request/result/derived demand/learning throughout origins, answers, receipts, blobs + indexes and retain only the user-ruled metadata; it is not achieved by removing this one ref. No ZDR, erasure, operator-blindness or multi-caller isolation claim ships in U4.
- D5 `answer` = independent store representation of W Answer facts, caller, original request-record ref + explicit basis snapshot/serial position. Typed refs preserve exact checker output/input/export bytes without violating whole-envelope J1. Record/ref bindings agree on operation, caller, input, entry revision + archive/certificate identity. A verification-profile record/descriptor retains the exact U2 profile bytes and its U2 profile_id; that id is not its store envelope address. Receipt identities name exact executed build/profile/comparator bytes/config/source/targets, with human labels separate. Admission evidence additionally preserves EntryRef, subject/target binding, independent expected snapshot/challenge, allowlist/config identities, solution/challenge exports, complete per-claim/per-profile kernel results + time; large reports are bounded referenced evidence, not unlimited inline lists. U12 decides whether those facts establish admission; U4 proves preservation/reference agreement, not truth of a supplied `accept`.
  - Delivery receipts preserve caller/principal/credential/scope/policy at receipt, named request/answer/entry event, exact offered/transferred BlobRef, terms, build/profile/comparator identities + time. No receipt asserts caller receipt or caller-side re-check merely because sending started. Content-address graph stays acyclic: request→content; answer/receipt→request/evidence; receipt→entry tuple/projection, not enclosing entry hash; no record includes its own enclosing generation's address. Pre-existing basis generation or a defined logical serial position may be recorded instead.
  - (ruled R7) Initial delivery event = `reference_issued`; U8 owns issuance semantics and any later distinct transfer/ack event. Do not infer completed transfer, caller receipt or re-check without corresponding evidence. This internal receipt meaning does not change frozen public Receipt; any public shape/status change requires coordinated W re-instantiation under its owner.
- D6 Service-generated row ids, answer ids + opaque cursor handles = 128 OS-random bits rendered as exactly 32 lowercase hex characters (valid token/cursor grammars). Caller-supplied idempotency keys retain all accepted W bytes; caller identity issuance = U6. Entropy failure = typed operational failure, no predictable fallback/publication. Freshness checks include committed state + staged batch/live table as applicable; never overwrite/rebind on collision. Time/entropy enter pure apply as explicit validated facts. Random ids do not establish volume secrecy; public global seq/revision counters remain visible.
  - (ruled R8) Finite specified collision resampling, then failure; freeze bound + exhausted outcome before tests. Entropy quality is an OS residual; collision handling is executable/proved. Cross-process/retired-handle nonreuse states its probabilistic assumption or explicit instance identity; a live-table check alone is not that stronger guarantee.

### G Generations + CURRENT (format; durable operations in U4B)

- G1 Independent authority = ordered committed batch/effect segments selected by the generation, not loose-directory contents and not index membership. Every successful durable effect introduces its typed primary domain/audit/evidence refs + operation/order facts into this stream. A pure fold from genesis defines logical state. Secondary checkpoints/deltas/pages accelerate that fold; none is a second authority. Structural nodes are selected through typed heads, not recursively included in a segment that would hash itself. Orphans are not members.
  - Generation = store id, nonnegative number, previous-generation identity, versioned required store/write-compatibility profile, fixed counters, a fixed number of authoritative/index/checkpoint/history heads + created_ms. Genesis: number 0, no predecessor, empty authority/heads, catalog revision 0, no allocated changes. Normal nonempty durable batches advance number once; no-effect/no-audit batches need no generation. Entry/row revisions start at 1. Catalog increment rules, all stream ordinals and which command allocates them are exact Commands-v1 facts.
  - (ruled R9) Store `last_change_seq=0` at genesis; allocate a checked last+1. The final legal MAX value remains usable; never encode MAX+1. All internal numbers obey their complete-envelope domains, not just wire-visible counters.
  - (ruled R10) Previous-generation digest = archival provenance, not an operational startup edge. Verify the selected authority/history/domain closure, not superseded generations/checkpoints merely through lineage. All retained authoritative domain history still verifies, so startup remains growing work. The table marks each reference's operational/provenance status; no silent lazy omission from the chosen closure.
  - Fixed scalar/cardinality/profile/head bounds imply a finite encoded generation size independent of history count; publish the derived bound. No growing per-entry/row/caller/segment/top-chunk list in a generation. B1 measures observed bytes/cost and checks, not invents, this bound. Binary capabilities differ from committed store requirements; B2 establishes their read/write/preserve intersection.
- G2 CURRENT = bounded canonical exact-field regular control file with format `fvapi.store.current.v1`, generation address + number; address/number equality with the named generation is mandatory. Stable root layout = CURRENT, persistent LOCK, records/, blobs/, tmp/, plus recognized own-format unpublished temporaries in their actual final parents/root. Temporaries never satisfy references or become selectors. Normal open is never init/repair/fallback. G2's init/replacement protocol is specified in U4B P/C/R.
  - (ruled R20) CURRENT has exactly three members: `format`, `generation`, `number`. Store identity comes only from the selected generation; no redundant `store_id` member. Payloads-v1 fixes this exact shape, not an optional undeclared field.

### I Indexes + reads

- I1 Every derived view is a declarative query over G1's independent authority fold. Entries: unique EntryRef→immutable revision, id→all admitted revisions + explicit greatest revision. Spec/digest/subject postings: distinct retained EntryRefs satisfying frozen W1a, including its separate-target existential rule. U5 owns candidate eligibility/ranking, not an index's silent historical-revision deletion. Rows: (caller,id)→latest revision. Open-miss coalescing: (caller, complete normalized Keys)→one latest miss-origin row in queued|being_proved, never a request-origin row. Request idempotency: (caller, request operation, key)→immutable original normalized intent + origin/row. Changes: allocated seq→that exact historical row revision, not the latest row. Changes are append history, not automatically an unbounded current-state TreeMap. Ref membership/caller/uniqueness/order + complete coverage are checked independently; a dropped binding cannot erase its own oracle by becoming an orphan.
- I2 Current-state representation = canonical sorted immutable bounded checkpoint chunks + an exact committed ordered tail, rebuilt into Std.TreeMap views. Never serialize Lean's internal map layout. Checkpoint identifies its index kind, exact authoritative commit/operation prefix + source identity; row seq alone cannot name entry/audit-only commits. Keys are strictly ordered/unique under frozen byte/numeric/composite comparators. Tail is precisely the later effects, applied once with no gap/overlap/duplicate; either reuse authoritative segment effects or prove any delta projection equivalent. Tail count + encoded bytes have hard bounds. Before a batch would exceed either, synchronously construct/adopt a complete checkpoint for a specified prefix and retain its entire suffix in the same root commit. Failure leaves old heads selected. No committed over-bound tail. Background checkpoint adoption is later work requiring its own no-lost-tail proof. Checkpoint construction cost/write amplification/memory remain measured, not fixed-cost promises.
- I3 Every nonempty batch seals bounded immutable segment(s); no mutable content-addressed open segment. Exact schemas give stream identity, ordered effect/record refs, ordinal/sequence ranges + counts. Request/answer order = committed event order, never random id/wall time; changes retain historical revisions; attempt histories pin their own fold. Segment count/bytes bounded under valid format/runtime profiles; histories grow through references, not a flat root list.
  - (ruled R11) One specialized immutable bounded-fanout append directory for authority + paged streams: bounded leaves/children, exact ordered disjoint ranges/counts/levels, minimal-height append shape; copy only the rightmost spine and grow height. This is not a measured optimum or a general arbitrary-update disk map. Payloads-v1 instantiates the layout, including empty stream, gaps, fullness/height and node byte bounds, before code. The proposed fanout/leaf ceiling 1024 is a format choice to freeze, not an unmeasured capacity guarantee or runtime knob that rewrites old formats.
  - Complexity: seek O(height) bounded directory reads, then intersecting bounded nodes/segments + emitted record bytes; under the specified append shape height is logarithmic in segment/leaf count. State caller-filter scan + decoding costs separately. The draft's undefined `O(page + log)` claim is not retained. First/deep page + height/checkpoint boundaries belong in B1.
- I4 Ordinary reads pin one committed generation/view through completion; mutations use C2's serial-position result, never recompute their reply from a newer global root. Handles bind store instance + generation, caller, collection purpose/allowed consuming route, resource identity/revision, normalized semantic filter/order version + immutable position. Lookup-issued other/key-match handles are consumed by `matches`; attempt handles pin row id/revision/history. Cursor/attempt_cursor + limit are transport controls, not membership filters. Changed valid limit preserves collection/order/position; same handle never advances in place. Repeat with the same parameters returns the same logical page until expiry. Every continuation authenticates/authorizes independently; unknown/expired/foreign/wrong-context→400 malformed, without disclosing foreign state.
  - Bound table count/bytes, retained snapshots/reply capacity + monotonic lifetime. Required continuation capacity is reserved before emission, and before mutation acceptance if needed by its successful result; full→busy, never falsely terminal/truncated/empty-progress page or eviction/rebinding of a live handle. Pins release on completion/expiry/close; disk retention is not a substitute for bounded in-memory retention. No truncation of a record; W5 progress + single-oversized-first-item exception hold. U5/U13 define order/membership; U7/U10/U13 own their declared page-byte budgets. `rows/changes` remains cursorless exclusive-since, increasing-seq, one fresh committed generation per call; last_seq/more semantics stay frozen.
  - (ruled R12) Process-local handles; service restart/deploy/rollback invalidates them → 400 `malformed`. The `docs/api.md` clarification states that cursors do not survive a service restart; document limit-change + lookup→matches behavior as well. Compatibility tests reject old handles and reissue fresh ones. No W shape amendment; restart-stable authenticated/persisted cursors remain deferred.

### Q Store-level semantics

- Q1 Persist (caller, operation=request, idempotency key)→(original normalized intent, origin + row id) in the same commit as creation, for store lifetime this phase. Intent = decoded typed statement + optional artifact hash + optional note, excluding key/receipt-time metadata. Exact equality: absent differs from present-empty; source/note whitespace, line endings + Unicode scalars unchanged; JSON member/escape/whitespace spellings do not alter decoded semantics. A digest may accelerate, never replace, exact comparison. Credential replacement preserves caller namespace. Equal replay returns the original row's state at C2's serial position, including closed states, with 202; no second origin/row/count/change. Required replay audit history is D4's explicit separate effect. Different intent never silently returns unrelated old success or creates a second row; binding/row remain unchanged. Storage exposes a distinct typed mismatch independent of HTTP mapping.
  - (ruled R13) Map typed idempotency mismatch to 400 `malformed`, detail = `idempotency_key reused with a different request`; document that detail + the equality condition. The store retains its typed mismatch result; no new wire code. Any frozen grading change follows the user-approval + original-firing rule. No key expiry.
- Q2 Coalescing = caller + complete supplied optional Keys tuple, preserving presence + exact typed scalar bytes; JSON order irrelevant, no case/Unicode/source folding or dropped supplied key. Only latest open miss-origin rows (queued|being_proved) qualify. Accepted miss either creates immutable origin + first queued revision or increments exactly that row's count/revision and allocates a new change. Request/answer facts, row mutation, change history + all coalescing/index effects are one command/commit. Closing removes the open binding atomically; later miss creates a new origin/id; request rows retain count=1. Counts mean accepted miss calls, not exactly-once logical requests: uncertain unkeyed retry can increment again. Overflow rejects the whole command with no partial effect. U13 later proves legal closure/reopen/expiry transitions over this primitive.
- Q3 Caller-owned request/content/answer/row/attempt/delivery histories and idempotency queries use explicit caller arguments, caller-preserving joins + authorized refs at the pinned generation. Raw structural/CAS lookup is internal; object-address knowledge/orphan presence is no grant. Shared admitted library entries/profiles/archives follow U6/U8 delivery access, not admitting caller as universal ACL. This phase provisions one founder and checks structural attribution/mismatched refs; it does not claim authenticated multi-caller route noninterference, ZDR or volume confidentiality. Attribution follows E4's literal caller-id rule without weakening the user ruling.

### T1 Claims (A definitions; B persistence refinement; C credited integration)

Reviewed independent definitions = `FvapiSpec/Store*.lean`; closed claims = `FvapiSelf/Store.lean`; proofs = `FvapiProof/Store*.lean`; shipped code imports none of these audit modules. Minimum promises, each with inventory call paths + obligation rows:

- `EnvelopeExact` + `CurrentExact`: production canonical bytes/typed decoders and all E2/G2 outcomes equal the independent byte/schema relation on every byte string and admissible profile/reference; success iff its exact supported admissible encoding, staged unsupported/corrupt distinctions included. Admissible encode/decode round trip is a corollary, not completeness by itself. Blob reads are raw-byte checks, not JSON.
- `ApplyExact`/`BatchExact`: production typed transition/results/authority effects equal the independent serial relation for every valid state + command + explicit external facts. Failed command leaves semantic state/index/counter/history unchanged; any retained failure audit is a separately declared complete effect. Includes expected-revision conflicts, immutable origin/challenge, safe last-counter allocation, exact idempotency replay/mismatch, request count=1, coalescing/closure and caller/reference preservation. U13 policy assumptions remain named until its unit discharges them.
- `IndexExact`: after every admissible batch, checkpoint+tail/current/history representations equal declarative fold/filter/range results over independently selected authority, with prefix coverage/order/uniqueness/completeness + no skipped/repeated delta. This cannot be proved by enumerating the index being checked.
- `SnapshotExact`: reads/pages use only their pinned generation + caller/collection/resource/order/position; retry/limit/expiry/capacity behavior and full-item/progress decisions match I4/W5. Runtime/native memory retention is separately tested.
- `CommitOrder` + `FailureExact`/`NoFalseSuccess`: from a validated durable base, every success-completion event follows original-description write/sync/close, immutable publication + required dependency/file/name/new-ancestor barriers, generation barrier, CURRENT write/sync/close/replace/root barrier and committed snapshot install. Verified orphan reuse participates. Terminal storage failures cannot produce false success, root rewind or later publication by the poisoned writer; command-local failures are distinct. Namespace backend + retry/cleanup policy = Syscalls-v1, not an unstated POSIX slogan.
- `RecoverySound` splits positive crash completeness/durability from defect refusal. Healthy crash-only execution from an acknowledged initialized store, under Crash-v1, reopens successfully at the latest acknowledged committed prefix or its complete in-flight extension, preserving every acknowledged effect, never a mixture/dangling ref/orphan promotion/earlier prefix. Refusal is not an allowed healthy-crash result. Single-writer reply discipline + the oracle define the allowed in-flight generation precisely, including partial completion release. Repeat crash/recovery preserves the property. Before init success an incomplete store may refuse; after init success an empty genesis must reopen. Malformed/corrupt/unsupported graphs + operational recovery errors fail closed by a separate exact refusal relation; persistence-error cases do not inherit healthy-storage availability.
- Crash-v1 assumptions: file bytes/inodes and directory bindings persist independently before their respective barriers; unsynced state may disappear/reorder/tear. Successful file barriers preserve the covered bytes; directory barriers preserve the relevant names/new ancestors, not arbitrary recursive payloads. After durable initialization, interrupted same-parent CURRENT replacement is crash-atomic old-or-new, never missing/torn; this is a qualified filesystem assumption, not inferred from live rename atomicity. Immutable files, stable directory/lock ownership and no out-of-band writer are explicit assumptions. If the supported stack cannot supply them, narrow support/claim through an explicit ruling rather than permit universal refusal.
- `PathSafe`, lock lifetime, allocation and lifecycle policies enter the obligation matrix: pure decisions/refinement proven where expressible; syscall wrapper/native guard/descriptor synchronization tested residuals. U3 HACL*/FFI boundary remains explicit: hash comparison observes the configured digest operation; no new SHA-256 injectivity or Lean functional-spec/equality axiom. Entropy, compiler/runtime, libc, OS, qualified filesystem/flush honesty remain named residuals. No proof of hardware durability, admission truth from stored status, or full product verification is implied.

### C Commit protocol (one writer)

- C1 One writer under the lifetime process lock, FIFO admission queue. Acceptance = atomic successful bounded reservation/enqueue, not parsing, reply allocation or durable acknowledgement. Account command count + all retained encoded/decoded/input bytes/references + outstanding reply state, separately bound active batch and cursor/pinned-view retention. Distinguish these from resident current-state/history views and U7 transport buffers; no total-memory bound follows from queue bytes alone. Capacity-full→busy before acceptance, no command effect. Positive limits selected in U4C; deterministic controls force each independently. Cancel before acceptance→no effect; accepted disconnect/cancellation detaches reply, never silently retracts/repeats a possibly committed command. Release reservations on every terminal path.
- C2 Drain already-waiting FIFO prefix under count/byte bounds, no intentional idle delay. Given explicit time/entropy facts, pure apply runs each command transactionally against preceding successful staged effects. Validation/CAS/mismatch/overflow failure has no partial semantic allocation/record/index effect; unrelated valid commands continue. Each success result is fixed at its serial position, even if a later same-batch command advances the row. No staged state visible to ordinary readers. Commands computed off-writer declare basis snapshot/record revision and revalidate/recompute in the current working state, or explicitly record the earlier snapshot result under their owner's contract. Audit/domain/answer/idempotency/coalescing facts form one compound command. Required audit-only effects can make a generation; wholly no-effect/no-audit batch need not publish one, but relies only on an established durable base (R2). Every accepted pending command gets one terminal completion/error or documented closed transport, never indefinite waiter leakage.
- C3 Build the full candidate graph; publish immutable objects + establish required dependency barriers, then generation + its barriers, then CURRENT replacement + root barrier. G2 CURRENT replacement = exclusive same-root temp → full write → original-fd sync → explicit close → atomic rename-over CURRENT → sync retained root directory. Only after every required step succeeds install the committed in-memory snapshot and release successful command completions; validation errors remain errors. All successful new-fact commands in the group share this durability point. A crash after it but before some replies can leave unacknowledged effects present. Acknowledgement in the model = store success-completion event, not queue admission or proof of client receipt.
  - (ruled R15) Uncommitted object publication order may vary; batch/wave barriers cover every newly needed file/name/unproven reused binding + new ancestor before generation publication. Incomplete orphan graphs are harmless because only a selected complete generation is served. Keep generation/CURRENT last + all required ancestor/dedup barriers. Shared safe directory barriers may be coalesced; no directory is omitted because this invocation did not modify it.
- C4 Validation errors are command-local; terminal storage/publication/barrier errors poison the writer. Before attempting CURRENT replacement, abort candidate publication with previous root authoritative + retained orphans. Once replacement succeeded or completion is ambiguous, no success/rollback claim; preserve evidence for recovery. Reject later mutations busy, publish no later generation, settle pending commands with known-not-committed/indeterminate internal outcomes as applicable. Emit a content-free event + founder-visible signal through an independent path that does not require committing to the failed store. Never retry a terminal persistence error into successful durability or rename an old root back. A hung syscall is not a successful operation: U7 watchdog/lifecycle owns hangs; queue bounds do not bound commit duration.
  - (ruled R16) Retain frozen F3's conservative external classification/no-success after a required failure at/after rename; the crash oracle still records completed barriers. Do not erase the completed-root-barrier fact internally or claim the bytes rolled back. A transport/reply loss alone does not retroactively fail an already successful store commit.
  - (ruled R17) Poison rejects new reads as unavailable + new mutations busy; previously pinned reads may finish their old validated view. Map only through existing route-valid errors. Health/founder signal exposes poison.
  - A persisted request idempotency binding can identify its original row after validated restart. Row changes expose committed revisions, not a universal call/transaction status oracle. Unkeyed lookup/check/admit/request operations can commit without an observed reply; retries can append another answer/coalesced miss. No exactly-once inference from absence in a feed.
- C5 Check every numeric field against its store schema/U3 J1 before publication: counters, internal generation/stream numbers, sizes + timestamps. Command-local overflow→that command fails unchanged. A generation/batch-wide overflow→entire candidate batch fails without publication; do not charge it to one command and commit the others. No wrap/saturation/MAX+1 sentinel. Owning routes map typed overflow through existing outcome relations, never an invented wire code.

### R Initialization + lock + recovery

- R1 Acquire exclusive nonblocking `flock(LOCK_EX|LOCK_NB)` on the stable regular no-follow LOCK inode before reading CURRENT, publishing genesis or mutating an existing store. Kernel lock release on process exit does not commit its objects. Failed open/init closes each acquired descriptor once; native/process tests cover inheritance, duplicate opens, lifetime + cleanup.
- R2 Explicit init is separate from normal open. Init creates/syncs required directories + ancestors, valid genesis and CURRENT under the same exclusive lifetime + durable-root protocol; initial CURRENT creation cannot clobber an existing control file. Success waits for root + newly created root-parent namespace durability. Incomplete pre-success initialization is preserved/refused, never automatically promoted/overwritten. An acknowledged empty genesis must open.
  - (ruled R19) Init accepts only an absent destination under a trusted pinned parent and creates root exclusively. Ordinary open of missing/invalid CURRENT refuses and never creates a replacement store.
  - Open under R1 reads CURRENT once, validates exact canonical control schema/address/number agreement + the selected generation's store identity, then visits each object in the chosen operational closure once with visited/cycle handling. E2 validates bytes/class/kind/size/schema; cross-check domain/caller/revision/sequence/reference bindings + authority fold against checkpoints/tails/history/indexes. Full startup verification includes every byte selected by R10's closure; no object is silently exempt because hashing is expensive. Later disk reads validate again or use already-validated immutable cached bytes; startup does not prove permanent immunity to later corruption. Missing/corrupt/unsupported/IO defect→refuse service + independent content-free diagnostic/founder signal; never promote orphan, select older root, repair or initialize over damage.

- R3 Recovery deletes nothing. Recognized temps in root/shards/tmp/ + unreferenced blobs/records/generations remain unchanged and excluded from committed discovery.
