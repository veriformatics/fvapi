## J JSON profile codec (shipped `Fvapi/Json/*.lean`, Std-only)

- J1 Values: `Value` = `null` | `bool b` | `int n` (`Int`) | `str s` | `arr xs` | `obj ms` (`List (String × Value)`). Depth: a scalar 0, a container 1 + the largest child depth (empty container 1). `Valid v` := every integer satisfies |n| ≤ 2^53 − 1 ∧ every string + key has ≤ 65,536 UTF-8 bytes ∧ depth ≤ 32 ∧ every object's keys strictly ascend in UTF-8 byte order (unique). A successful decode returns a valid value (claim `DecodeValid`); the printer is total on all values, its laws hold on valid ones. Strings may hold U+0000: consumers that cross path, argument, identifier or source conventions validate their own semantics.
- J2 Grammar (reviewed spec `FvapiSpec/Json.lean`, over bytes): RFC 8259 JSON text = ws value ws, ws ∈ {0x20, 0x09, 0x0A, 0x0D}; any value at top level (route rules live in J7 + W). Literals `null` `true` `false`. Integer = `0` | `-?[1-9][0-9]*` with |n| ≤ 2^53 − 1 (no `-0`, fraction, exponent, `+`, leading zero; an out-of-range lexeme has no derivation). String = `"` element* `"`, element = an escape (`\"` `\\` `\/` `\b` `\f` `\n` `\r` `\t`, `\uXXXX` with hex digits of either case; a high-surrogate escape only immediately followed by a low-surrogate escape, the pair denoting one scalar; a lone surrogate escape has no derivation) or a raw scalar c ≥ U+0020, c ∉ {`"`, `\`}, as the bytes `String.utf8EncodeChar c` (Lean core's encoder: overlong forms, encoded surrogates, bytes above U+10FFFF, stray continuation bytes have no derivation). Arrays + objects per RFC 8259 with ws around tokens; an object denotes its members in text order, duplicates kept (J3 decides them). A leading BOM, trailing non-whitespace, raw control characters in strings have no derivation; DEL, escaped NUL, U+2028/U+2029, U+FEFF inside a string and noncharacters are content (the profile is not I-JSON).
- J3 Outcome (`FvapiSpec.Json.Outcome`, in this precedence): `lexicalDepth b > 32` → `tooLarge`; else no derivation → `malformed`; else the derived value has a string or key over 65,536 UTF-8 bytes → `tooLarge`; else an object with two members whose decoded keys are equal → `duplicateKey`; else `ok (canon v)` (members stably sorted by key bytes, at every level). `lexicalDepth` = the largest count of open `[`/`{` bytes outside string literals in a left-to-right byte scan (a closing byte at level 0 stays at 0); on a grammatical text it equals the value's depth (proof obligation; the scan helper's invariant keeps level ≤ top). Consequences: `x` + 33 `[` → `tooLarge`; an unclosed string holding 33 `[` → `malformed`; a 65,537-byte string followed by `x` → `malformed`; an over-cap string + a duplicate key → `tooLarge`; a duplicate key followed by garbage → `malformed` — so a decoder may not stop early at an over-cap string or a duplicate (later syntax dominates), though it need not retain over-cap text while it continues.
- J4 Canonical text (reviewed spec function `canonical : Value → List UInt8`): no whitespace; members in stored order (valid values: ascending key bytes); integers in shortest decimal, `-` only when negative; strings escape exactly `"` → `\"`, `\` → `\\`, U+0008 `\b`, U+000C `\f`, U+000A `\n`, U+000D `\r`, U+0009 `\t`, every other U+0000–U+001F and U+007F → `\u00xx` (lowercase hex); every other scalar raw UTF-8 (`/`, U+2028, U+2029, noncharacters included). This is jq's `-S -c` output without its final LF on every valid value (consultant-15: 93 cases incl. every scalar U+0000–U+009F, boundary scalars + non-BMP keys equal under jq 1.8.1; not JCS, whose key order is UTF-16); `verify/profile.json`'s id reproduces (`sha256:d6ab2e9f…`). U2 hashes the profile with only its root `id` removed (U2's obligation).
- J5 Shipped functions: `Fvapi.Json.decode : ByteArray → Except DecodeError Value` (`DecodeError` = `malformed` | `tooLarge` | `duplicateKey`), `Fvapi.Json.print : Value → ByteArray` (members in stored order). `Value.object ms` returns an object whose outer members are the stable key-byte sort of `ms`; it neither drops repeated keys nor changes child values; it is valid when keys are bounded and distinct, children are valid and the resulting depth is ≤ 32 (callers build nested objects under the same invariant). `get? key` on an object returns the value of the first equal key in stored order; an absent key or a non-object → `none`; a present JSON null → `some .null`; keys compare as complete decoded scalar sequences (no normalization, no case folding). Each `asStr?` / `asInt?` / `asBool?` / `asArr?` / `asObj?` returns its constructor's payload exactly and `none` for every other constructor (no coercions). Laws proven over all `Value` inputs; no shipped judgment decides by `BEq Value` without a proof that it agrees with `=`.
- J5 Resources: decode reads byte indices without copying the input into a list; the lexical scan is linear in input bytes; integer accumulation stops once a range violation is established; string, whitespace, digit + sibling loops and the post-passes use tail iteration (compiled to loops) or explicit work storage, with builders that never copy prefixes. Object sorting costs comparisons: target `O(N + Σ Kᵢ log(mᵢ + 1))` work (N input bytes; mᵢ members + Kᵢ key bytes of object i) and O(N) live storage; duplicate detection = sort + adjacent compare (the spec's `Nodup` is a definition, not the algorithm). The depth check bounds recursive container descent; sort + helper stack use (Std's `mergeSortTR₂`: logarithmic recursion) is accounted separately and the compiled call path is tested — logical termination is not a count of machine frames. A concrete fuel bound is proven sufficient for every input; no `partial` def is reached by a claim. Printer correctness is total over `Value`; resource statements say whether they cover all values or valid ones. Transport body limits (U7) live outside the codec's all-input outcome relation.
- J6 Claims (`FvapiSelf/Json.lean`, proofs `FvapiProof/Json.lean`, inventory + obligation rows): `DecodeExact := ∀ b r, decode b = r ↔ FvapiSpec.Json.Outcome b.data.toList r` (exact, total, deterministic outcomes incl. errors; unique normalized accepted results); `DecodeValid := ∀ b v, decode b = .ok v → FvapiSpec.Json.Valid v`; `TextUnique := ∀ bs v v', FvapiSpec.Json.Text bs v → FvapiSpec.Json.Text bs v' → v = v'` (raw grammar determinism, from the raw parser's completeness); `PrintExact := ∀ v, (print v).data.toList = FvapiSpec.Json.canonical v`; `RoundTrip := ∀ v, FvapiSpec.Json.Valid v → FvapiSpec.Json.Outcome (FvapiSpec.Json.canonical v) (.ok v)`; the J5 constructor / lookup / projection laws (`ObjectLaw`, `GetLaw`, `AsLaws`). Derived corollaries, stated + proven: `decode (print v) = .ok v` for valid `v`; `canonical` injective on valid values. The grammar-depth correspondence and the normalization invariants behind `DecodeValid` are proof obligations. Spec sanity examples on the inductive grammar use constructor + inversion proofs (`decide` covers their decidable side conditions only).
- J7 JSON-route ruling (A12): after authentication and the route's transport/framing policy, a body designated JSON receives the complete J3 outcome before route-field validation. A successful JSON-route body must have an object root; another root yields `malformed`. The root container counts depth 1. String/key limits count decoded UTF-8 bytes; integer spelling is J2's. `malformed` and `duplicateKey` map to HTTP 400 with their API error codes; `tooLarge` maps to HTTP 413 `too_large`. Raw checker requests and archive transfers bypass JSON decoding and keep their exact-byte contracts. W fixes precedence among field/schema errors after JSON validation. `docs/api.md`'s JSON-profile paragraph states these refinements.

## S SHA-256 (HACL*, vendored C through FFI)

- S1 Vendor: upstream `https://github.com/hacl-star/hacl-star` `dist/gcc-compatible` scalar SHA-2 at commit `f557259007db9933442dde10aa995c1b00bd3446`: `tools/vendor-hacl.sh [COMMIT]` fetches exactly that commit, verifies the fetched commit identity and extracts the allowlisted regular files as raw git blobs (`git cat-file blob`; independent of checkout filters or line-ending settings) under `vendor/hacl-star/` with their layout — the 15-file closure (110,719 bytes: `Hacl_Hash_SHA2.{c,h}`, `internal/Hacl_Hash_SHA2.h`, `Hacl_Streaming_Types.h` + internal, `Hacl_Krmllib.h` + internal, `krml/internal/{types,target,compat}.h`, `krml/lowstar_endianness.h`, `krmllib/dist/minimal/{fstar_uint128_gcc64,FStar_UInt128,FStar_UInt_8_16_32_64,LowStar_Endianness}.h`) plus `dist/LICENSE.txt` (MIT) + the root `LICENSE` (Apache-2.0), every file header kept. `lock.json` = upstream, commit, per-file sha256; a locked replay (no argument) must regenerate identical bytes + lock; only an explicit reviewed update re-pins. Gate stage `vendor`: the tree = the lock (probes: one changed byte, a missing file, an extra file, an upstream without a dependency row). Renovate (custom regex manager, `git-refs` on `main`) proposes the commit by editing `commit` alone, so its PR is red on `vendor` by design until `tools/vendor-hacl.sh <commit>` relocks the files in the same PR; source pins, file hashes, notices + native evidence change together. The no-argument re-vendor (identical bytes + lock regenerated from the locked commit) is the acceptance check for any pin bump. `docs/dependencies.md` row: scanner = OSV commit query + upstream advisory endpoint (declared gap: no lockfile scanner covers vendored C).
- S2 Build: Lake compiles `Hacl_Hash_SHA2.c` + fvapi's shim `c/fvapi_sha256.c` with the toolchain's C compiler (`getLeanCc` / `buildLeanO`), `-std=gnu11 -O3 -fPIC`, include roots `dist/gcc-compatible`, `dist/karamel/include`, `dist/karamel/krmllib/dist/minimal`, native `__int128` (no `KRML_VERIFIED_UINT128`, no SIMD / SHA-NI / EverCrypt); every vendored header is a traced input (a changed header rebuilds the object); a static archive linked through `moreLinkObjs` into the targets that need it.
- S3 API (`Fvapi/Hash/Sha256.lean`): `sha256 : @& ByteArray → ByteArray` (32 bytes), pure + total: an input below 2^32 bytes goes through `Hacl_Hash_SHA2_hash_256` itself (HACL's own verified composition, end to end); a larger one through HACL's verified block functions (`Hacl_Hash_SHA2_sha256_init`, `_update_nblocks`, `_update_last`, `_finish`) on a private stack state, over block-aligned chunks each below 2^32 bytes — no length narrowed, nothing allocated but the 32-byte result; an input of 2^61 bytes or more (beyond the supported domain and any addressable array) aborts the process (`lean_internal_panic`; Lean's `panic!` would continue with a default value), never a prefix digest. Streaming without a shared mutable object: `Sha256.State` is a pure value (32-byte chaining state, the buffered partial block < 64 bytes, the total length) with `Sha256.init`, `Sha256.update : State → @& ByteArray → State` (hands whole blocks to HACL, buffers the rest) and `Sha256.finish : State → ByteArray`; `Sha256.ofReader (read : IO ByteArray) : IO ByteArray` folds chunks until an empty one and propagates any read error (no digest of a prefix); `sha256File path := ofReader` over the file's chunked reads. `hex : ByteArray → String` maps each byte to exactly two lowercase hex digits (claim `HexExact`). C ABI = Lean 4.35's (borrowed read-only input, no world argument, `lean_alloc_sarray` output, a valid pointer for empty input); the header's argument order is pinned by S1 and checked by S5's vectors. Internal-API preconditions relied on (not a public header contract; pinned by S1 + S5): `update_nblocks len b st` processes `len / 64` whole blocks and ignores the remainder; `update_last totlen len b st` takes `totlen` = all bytes hashed (in bytes, < 2^61) and `len` < 64 trailing bytes; the trailing-block pointer is valid even when `len` = 0 (an empty `ByteArray`'s `lean_sarray_cptr` is relied on). This replaces an IO API over HACL's malloc'd streaming state: the block functions remove allocation failure and state aliasing from the boundary.
- S4 Trust: SHA-256 = HACL*'s F*/Low* code, verified upstream for memory safety, functional correctness against its F* SHA-2 spec (written from FIPS 180-4) and secret independence — not a Lean theorem, a FIPS validation or a collision-resistance proof; trusted = F* + Z3, KaRaMeL extraction, the hand-written KaRaMeL helper headers, the C compiler, fvapi's shim + its orchestration of the block functions for inputs ≥ 2^32 bytes and across `Sha256.update` calls (upstream's streaming functor does this verified; fvapi's is small, reviewed, differential-tested); inputs below 2^32 bytes to `sha256` stay on HACL's own composition. Lean treats the block functions as opaque: no Lean-level functional spec and no equality axiom is claimed.
- S5 Tests: the byte-oriented NIST CAVP SHA256ShortMsg + LongMsg + Monte Carlo corpus pinned by bytes, the 10^6 × `a` vector; differential vs `sha256sum` on lengths 0, 1, 55, 56, 63, 64, 65, 119, 120, 127, 128, 4095, 4096, 1 MiB + generated, through the real native package-boundary executable; `Sha256.update` over generated splits (incl. empty chunks, 1-byte chunks, splits inside and across blocks) = one-shot; chunk arithmetic around 2^32 − 1, 2^32, 2^32 + 1 exercised through the same shim loop compiled with a small chunk ceiling; `ofReader` with a reader failing after a nonempty prefix → error, no digest; input bytes unchanged; concurrent Tasks; a standalone C harness under ASan + UBSan (system C compiler) runs the shim on the vectors + boundary lengths + small-ceiling chunking with zero leaks reported; `hex` checked against an independent encoder.

## F fsync shim (commit B; details freeze before B's blind suite)

- F1 `Fvapi/Sys/Fsync.lean` + `c/fvapi_fsync.c`: a small owned-descriptor wrapper preserves one writer descriptor / open-file description from creation and writes through the file durability barrier (a descriptor reopened by path can miss an earlier writeback error: fsync(2)); path strings are diagnostic context, not the identity of the committed object. Interrupted open / write / fsync calls retry under a bounded policy (exhaustion = error); each owned descriptor closes at most once, including after `EINTR` (close(2): a retry may close a reused descriptor); errno captured at once, the primary failure + any secondary close failure kept. Directory barrier = `fsync` on a descriptor of the directory (`O_DIRECTORY`). Ordering for U4: data → file barrier → rename → barrier on every modified parent (both on a cross-directory move) + newly created ancestors; a failure after the rename = durability indeterminate, never reported as success or as rolled back. Lean's `Handle.flush` (`fflush`) is not durability; U4 owns directory identity + the complete commit/crash protocol.
- F2 Tests: fault-injected open / write / fsync / close failures + retry exhaustion (operation + errno distinguished, no false success, no repeated close); the file barrier targets the writer's open-file description; host success on ext4 (root) + ZFS (`/srv/data`, `sync=standard` on vflab) = integration evidence; U15's live-host check asserts the store dataset's `sync` is `standard` or `always`; crash cuts belong to U4.

- U3 proves the decoder, printer + accessors against the reviewed byte grammar + canonical form; the grammar's fidelity to RFC 8259 + `docs/api.md` is a review ruling backed by the differential suite, not a machine-checked RFC equivalence; jq agreement is the reviewed canonical contract + differential evidence, not a theorem about jq.
